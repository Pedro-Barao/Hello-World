História da Computação • James Martin (1983)

📦 1. De Onde Veio a Sigla CRUD?

Em 1983, o britânico James Martin, pioneiro da Engenharia da Informação, cunhou o acrônimo CRUD em seu livro clássico "Managing the Data-Base Environment".

Martin demonstrou que 80% dos softwares corporativos do mundo orbitam em torno dessas 4 operações atômicas fundamentais:

  • C - Create: Inserir novo registro no banco (INSERT INTO).
  • R - Read: Consultar tuplas gravadas (SELECT pontual ou coletivo).
  • U - Update: Modificar atributos de um registro existente (UPDATE ... WHERE).
  • D - Delete: Remover uma tupla do armazenamento (DELETE FROM ... WHERE).
📸 Metáfora Lúdica do Álbum de Família Físico:
• Create: Colar uma foto revelada na folha do álbum.
• Read: Abrir o álbum para folhear ou procurar uma foto no índice.
• Update: Passar corretivo e corrigir uma data errada na legenda da foto.
• Delete: A foto borrou ou perdeu o sentido; você descola da página e joga fora no lixo.

⚠️ 2. A Caneta Laser do Cirurgião: A Cláusula WHERE e as Linhas Afetadas

Diferente do executeQuery() (que devolve um ResultSet), o método executeUpdate() retorna um número inteiro (int). Esse número indica exatamente quantas linhas no banco de dados foram realmente alteradas ou excluídas!

Se você executar DELETE FROM produtos WHERE id = 999 e esse ID não existir, o banco não gera erro! Ele apenas devolve 0. O DAO deve verificar return linhasAfetadas > 0; para que a View saiba avisar o usuário se o item foi realmente apagado ou não.

🚨 O Famoso "UPDATE sem WHERE" (Desastre de Produção):
A cláusula WHERE id = ? é a caneta laser de precisão do cirurgião. Se o médico acionar o laser sem apontar para a verruga, queima a sala inteira! Um UPDATE produtos SET preco = 0.0; sem WHERE zera o preço de todo o catálogo de uma loja em 1 segundo.

CRUD ENTERPRISE

Implemente o ciclo de vida completo de persistência (Create, Read, Update, Delete) com garantia determinística de integridade relacional:

1. Pacote e Entidade: br.com.starlog.model.Produto

  • Atributos Privados: Long id, String nome, double preco, int estoque.
  • Controle de Invariantes: Disparar IllegalArgumentException se:
    • nome for nulo ou tiver menos de 3 caracteres.
    • preco for menor ou igual a 0.0.
    • estoque for estritamente negativo (< 0).
  • Construtores & Métodos: Construtor de persistência (com id), construtor de negócio (sem id), getters, setId(Long id), setPreco(double), setEstoque(int) e toString() formatado.

2. Contrato da Interface: br.com.starlog.dao.ProdutoDAO

Declare as 5 assinaturas do contrato sem acoplamento a banco de dados:

public interface ProdutoDAO {
    void salvar(Produto produto);
    Optional<Produto> buscarPorId(Long id);
    List<Produto> listarTodos();
    boolean atualizar(Produto produto);
    boolean excluir(Long id);
}

3. Implementação Concreta: br.com.starlog.dao.ProdutoDAOSqlite

  • DDL Automático: Criação da tabela produtos (id INTEGER PRIMARY KEY AUTOINCREMENT, nome TEXT NOT NULL, preco REAL NOT NULL, estoque INTEGER NOT NULL); no construtor.
  • Validação de Linhas Afetadas: Tanto atualizar quanto excluir devem inspecionar int afetadas = stmt.executeUpdate(); e retornar afetadas > 0, sem ignorar o retorno do driver.
  • Ordenação Canônica: O método listarTodos() deve obrigatoriamente incluir ORDER BY nome ASC para estabilizar a renderização na interface.

4. Simulação de Negócio no Main.java (Ciclo Completo)

  1. [Create]: Cadastre dois itens (ex: "Teclado Mecânico RGB" e "Mousepad Speed XL"). Mostre os IDs autoincrement gerados.
  2. [Read]: Liste todos os produtos com exibição limpa em colunas no terminal.
  3. [Update]: Altere o estoque do Teclado para 15 unidades e o preço para 289.90. Verifique se o método retornou true e exiba o registro atualizado.
  4. [Delete]: Remova o Mousepad por ID. Teste a exclusão de um ID inexistente (ex: 888L) e comprove que o sistema lida com o retorno false amigavelmente sem travar.
  5. [Final State]: Execute listarTodos() e mostre que restou exatamente 1 produto no banco.
